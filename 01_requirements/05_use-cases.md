# ユースケース / ユーザーストーリー

> 機能要件（FR）を「ユーザー視点の流れ」で表現する。FRが点なら、ユースケースは線。
> 顧客との認識合わせに最も有効なため、プロトタイプと組み合わせて使う。

## 1. ユースケース図
```mermaid
graph TB
  Admin((システム管理者))
  UserA((ロールA ユーザー))
  subgraph System[本システム]
    UC1[ログインする]
    UC2[ユーザーを発行する]
    UC3[{{業務操作}}]
  end
  Admin --> UC1
  Admin --> UC2
  UserA --> UC1
  UserA --> UC3
```

## 2. ユースケース詳細

### UC-001 ログインする
| 項目 | 内容 |
|------|------|
| アクター | 全ユーザー |
| 目的 | システムを利用するため認証を通す |
| 事前条件 | 有効なアカウントを保有 |
| 基本フロー | 1. ログイン画面を開く 2. 認証情報を入力 3. 認証 4. ホームへ |
| 代替フロー | {{2段階認証コード入力 等}} |
| 例外フロー | 認証失敗 → エラー表示／一定回数でロック |
| 事後条件 | セッション確立・監査ログ記録 |
| 関連FR | FR-AUTH-001 |
| 関連画面 | SCR-001 |
