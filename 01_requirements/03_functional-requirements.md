# 機能要件（Functional Requirements）

> 各要件には **一意のID（FR-xxx）** を付ける。設計・実装・テストはこのIDで紐づける（トレーサビリティの起点）。
> 1要件は「検証可能」な粒度にする。「使いやすくする」のような検証不能な記述はNFRやデザイン指針に回す。

## 記法ルール
- ID: `FR-{{機能カテゴリ}}-{{連番}}`（例: `FR-USER-001`）
- 優先度: MoSCoW（Must / Should / Could / Won't）
- ステータス: Draft / Agreed / Implemented / Verified
