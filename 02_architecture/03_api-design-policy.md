# API設計方針（共通仕様）

> 個々のエンドポイントは `../03_detailed-design/api/` に書く。ここは**全API共通のルール**。

## 1. スタイル
- {{REST / RPC / GraphQL}}（選定理由を ADR に）
- バージョニング: パスに含める（`/api/v1/...`）

## 2. URL / リソース設計
| ルール | 内容 |
|--------|------|
| リソース命名 | 複数形・{{ケバブ/スネーク}}（`glossary.md` に準拠） |
| 階層 | `/api/v1/{resource}/{id}/{sub-resource}` |
| フィルタ/検索 | クエリパラメータ（`?status=active&page=1`） |
| ページング | {{offset/limit or cursor}}。大規模データはカーソル推奨 |

## 3. HTTPメソッド / ステータスコード
| メソッド | 用途 | 主な成功コード |
|---------|------|--------------|
| GET | 取得 | 200 |
| POST | 作成 | 201 |
| PUT/PATCH | 更新 | 200 |
| DELETE | 削除 | 204 |

| エラー | コード | 用途 |
|--------|------|------|
| 入力不正 | 400 / 422 | バリデーション |
| 未認証 | 401 | 認証切れ |
| 権限不足 | 403 | 認可NG |
| 不存在 | 404 | |
| 競合 | 409 | 一意制約・楽観ロック |
| サーバエラー | 500 | |

## 4. リクエスト / レスポンス共通形式
```jsonc
// 成功
{ "data": { /* ... */ }, "meta": { "page": 1, "total": 100 } }
// エラー
{ "error": { "code": "VALIDATION_ERROR", "message": "...", "details": [ /* ... */ ] } }
```
- 日時は {{ISO 8601 / UTC}}。
- エラーコードは機械可読な定数（`glossary` or 専用一覧で管理）。

## 5. 認証・認可
- 全保護APIは認証必須（`02_auth-and-access.md`）。
- 認可はリソース所有権を必ず検証（他ユーザーデータ露出の防止）。

## 6. 横断仕様
| 項目 | 方針 |
|------|------|
| レート制限 | {{}} |
| 冪等性 | {{POSTのIdempotency-Key 等}} |
| 相関ID | リクエストごとに付与しログに記録 |
| CORS | {{許可オリジン}} |
| 入力バリデーション | 全入力で必須。サニタイズ |
| ドキュメント化 | {{OpenAPI で管理し spec を参照}} |
